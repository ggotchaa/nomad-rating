# Памятка администратора платформы

Вход в `/admin`. В продакшене обязательна двухфакторная аутентификация (TOTP): включите её в «Безопасность» профиля.

## Очереди
- **Клубы** — проверка новых клубов: одобрить, отклонить или заблокировать с причиной.
- **Объединения** — заявки клубов на объединение профилей игроков.
- **RTTF** — импорт базы RTTF и конфликты «Это я».

## Игроки
- Поиск по имени, e-mail или ID.
- **Исправить рейтинг**: укажите новое значение и причину. Если выбрать турнир, рейтинг ставится «до» этого турнира и все следующие турниры пересчитываются (на время пересчёта на сайте виден значок «рейтинг обновляется»). Без турнира меняется только текущее значение.
- **Заблокировать / разблокировать** аккаунт: блокировка завершает все сессии, причина пишется в журнал.
- **Объединить профили**: ID источника и ID целевого; история источника переходит в целевой, источник удаляется. У обоих профилей не может быть аккаунтов.

## Споры
Список «Счёт неверный». Для матча можно сразу исправить счёт (`11:9 9:11 11:7`) — рейтинги пересчитаются. Затем «Решён» или «Отклонить» с ответом игроку.

## Журнал
Все изменения на платформе: фильтры по объекту, действию, e-mail автора, клубу и датам; «Показать ещё» листает дальше.

## Настройки
JSON-редакторы: коэффициенты Эло и RTTF a/b, стартовые уровни, комиссия, сроки удержаний, шаблоны уведомлений (`{club}`, `{table}`, `{startsAtText}` и другие поля события), тексты на трёх языках. Каждое сохранение пишется в журнал.

## Кабинет клуба
Откройте кабинет любого клуба в режиме просмотра — видно всё, что видит организатор, но сервер запрещает любые изменения. Кнопка «Выйти» в баннере возвращает обычный режим.

## Эксплуатация
- Резервные копии: `ops/backup.sh` (ежедневно, ротация 14 дней + 8 недель); восстановление описано в начале скрипта.
- Проверки: `/api/live` (процесс жив), `/api/ready` (база и Redis), документация API — `/api/docs`.
